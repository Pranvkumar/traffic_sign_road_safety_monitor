All numbers below are generated by `python scripts/summarise_results.py` from `experiments/runs/*/metrics.json` (copied into `outputs/reports/results_tables.md`). Every run also has a row in `experiments/experiment_log.csv`. Seeds: 42 everywhere (VAE ablation: seeds 0, 1, 2). Model selection always used the **validation** split; each test set was evaluated once after selection.

## Decisions and interpretation

**Classification.** HOG features beat raw pixels by a wide margin (90.0 % vs 81.5 % test accuracy) with fewer parameters. The NumPy CNN has the best test accuracy (91.3 %) and calibration (ECE 0.010) but was selected *against* on validation macro-F1 (0.850 vs 0.871) after only 8 epochs; it was still improving, so more epochs would likely change the ranking. HOG-MLP is deployed because it won on validation and is ~30× faster to train. Weakest classes (HOG-MLP test recall): pedestrians 42 %, end-of-no-overtaking 45 %, end-of-all-restrictions 50 %. Most common confusions are between speed-limit numbers (80→30: 62, 30→50: 45, 100→120: 38) — the 32×32 crops lose digit detail. Confusion matrices: `outputs/figures/confusion_*.png`.

**Detection — the weakest component.** v1 (grayscale HOG, 7.5 k hard negatives) was effectively unusable (test AP@0.5 ≈ 0.001–0.004). Diagnosis showed no train/inference mismatch: ground-truth crops scored 0.87, but 2.4 % of *random* background windows scored above 0.5, i.e. thousands of false alarms in the ~133 k windows per image. v2 added colour-opponent features and two rounds of hard-negative mining (92.5 k negatives): validation AP@0.5 rose from 0.010 to 0.131 but **test AP@0.5 is only 0.011**. The validation set is a single drive (172 images), so the threshold chosen there transfers poorly to the two test drives. The MLP scorer saturates (scores ≥ 0.95 on many background windows → ~97 false positives per image). Signs in this data are small (median 31 px; 23 % of test signs < 16 px, the smallest searched size) and seen against dense roadside clutter. **Conclusion:** a classical sliding-window detector is not adequate here; a CNN detector (YOLO/Faster R-CNN) is needed — see `docs/STATUS.md`. v1 metrics are kept in `experiments/runs/detector/metrics_v1_hog_gray_only_FAILED.json`.

**Segmentation.** The MLP pixel classifier (colour + position + texture + context features) beats logistic regression on validation and test (road IoU 0.826 vs 0.790). Known artefacts: the car bonnet is often painted as road (it is *ignored* in the metrics, but visible in overlays), and the model was trained on US comma10k images — on bright Indian concrete roads it misses large road areas and marks dry verges as road (see `outputs/predictions/001368_r_annotated.jpg`). Metrics are computed on a 1/2-resolution grid of the full-resolution prediction.

**Temporal (LSTM).** On the narrowly defined target in `docs/TEMPORAL_TARGET.md`, the LSTM beats both non-recurrent baselines (73.1 % vs 68.2 % mean-pool vs 61.7 % last frame) and degrades gracefully with 25 % missing frames (71.6 %). With 201 test tracks the standard error is about ±3 percentage points, so the LSTM vs mean-pool gap is suggestive rather than conclusive.

**VAE augmentation.** Adding 3,330 CVAE samples for the 8 rarest classes raised their mean recall from 70.2 % to 77.2 % (±1.5, 3 seeds) while overall accuracy was unchanged — a real but targeted gain. Sample quality is limited: images are blurry and only 57.9 % are recognised as their intended class by the real-only classifier. Generated images were used **only** in training; validation and test sets are 100 % real. Figures: `outputs/figures/vae_*.png`.

## Neural-network fundamentals (`python -m traffic_monitor.cli fundamentals`)

Data: 150 GTSRB training crops per class (6,450) and 40 validation crops per class; HOG+colour features. Results: `experiments/runs/fundamentals/results.json`.

| Demonstration | Result |
|---|---|
| Gradient check (central differences, float64) | max relative error ≤ 1.1×10⁻⁷ for ReLU/sigmoid/tanh MLPs (tolerance 10⁻⁵) — **pass** |
| SVD of a 32×32 sign | relative reconstruction error 18.7 % (rank 1), 8.5 % (rank 4), 4.0 % (rank 8), 0.7 % (rank 16) |
| Optimizers, 30 epochs | final train loss / val acc: full-batch GD 0.451 / 76.7 %, SGD 0.200 / 83.1 %, Momentum 0.010 / 87.2 %, Nesterov 0.010 / 87.0 % |
| McCulloch–Pitts | AND, OR, NOT gates reproduced exactly |
| Oja (modified Hebb) | weight vector aligns with PC1 (cosine 0.9996); plain Hebb weight norm explodes |
| Delta rule | recovers w = (1.491, −0.694), b = 0.300 vs true (1.5, −0.7, 0.3) |
| Hopfield (energy-based) | noisy pattern recalled exactly; energy −368 → −736 (never increases) |

One-factor ablations (HOG-MLP 372-128-43, Momentum, 20 epochs; train acc / val acc):

| Variant | Train | Val |
|---|---|---|
| baseline (He init, standardised inputs, L2 1e-4, no augmentation) | 100.0 % | 87.5 % |
| init = small N(0, 0.01) | 99.8 % | 88.3 % |
| **no input standardisation** | 89.1 % | **74.6 %** |
| L2 weight decay = 0 | 100.0 % | 87.5 % |
| L2 weight decay = 1e-2 | 98.9 % | 86.9 % |
| + 2 augmented copies of each training crop | 100.0 % | 88.0 % |

Input standardisation is by far the most important factor; the other single changes move validation accuracy by < 1 point on this small subset, which is within run-to-run noise (single seed). Figures: `outputs/figures/fundamentals_*.png`.
